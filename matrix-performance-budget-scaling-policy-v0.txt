Matrix Editor Performance Budget + Scaling Policy v0

Goal
- Keep editing/navigation smooth as matrix features grow (computed/dynamic cells, selection, paste).
- Provide concrete thresholds that trigger implementation strategy changes.

--------------------------------------------------
1) Target Performance Budgets (Latency Goals)
--------------------------------------------------

User-visible interaction budgets (desktop baseline)

- Single key navigation (arrow/tab/enter move focus)
  - Target: <= 16 ms p95
  - Hard ceiling: 33 ms p95

- Enter edit mode (F2/Enter/printable key)
  - Target: <= 24 ms p95
  - Hard ceiling: 50 ms p95

- Single-cell commit (valid draft -> committed)
  - Target: <= 24 ms p95
  - Hard ceiling: 50 ms p95

- Range selection drag update (visual feedback)
  - Target: <= 16 ms p95 per frame-equivalent update
  - Hard ceiling: 33 ms p95

- Paste apply (10x10 = 100 cells)
  - Target: <= 80 ms p95 total
  - Hard ceiling: 150 ms p95

- Paste apply (25x25 = 625 cells)
  - Target: <= 200 ms p95 total
  - Hard ceiling: 350 ms p95

- Recompute EV (no cyclic compute)
  - Target: <= 16 ms p95
  - Hard ceiling: 33 ms p95

- Cyclic compute pass (maxIterations=5, moderate dependency graph)
  - Target: <= 120 ms p95 total
  - Hard ceiling: 250 ms p95

Perceived responsiveness rules
- No interaction should block typing cursor feedback.
- If operation exceeds 120 ms, show non-blocking busy hint (not modal).

--------------------------------------------------
2) Size Thresholds (Rows x Cols) for Strategy Switches
--------------------------------------------------

Definitions
- `N = rows * cols` (body cells only; excludes headers/controls)

Tier S (small): N <= 144 (e.g., 12x12)
- Strategy: full render acceptable with memoized cells.
- No virtualization required.

Tier M (medium): 145 <= N <= 400 (e.g., up to 20x20)
- Strategy: strict memoization + selector-based subscriptions.
- Avoid global state updates on per-cell keystroke.
- Virtualization optional; usually off.

Tier L (large): 401 <= N <= 900 (e.g., up to 30x30)
- Strategy: row-window or column-window virtualization SHOULD be enabled in compact mode.
- Expensive derived recomputes MUST be incremental/debounced where safe.

Tier XL (very large): N > 900
- Strategy: virtualization REQUIRED.
- Non-essential visuals reduced (animations, heavy shadows, always-on metadata badges).
- Computed/cyclic recompute MAY be deferred to commit boundaries rather than each draft change.

Special threshold for computed-heavy matrices
- If computed/reference/cyclic cells > 25% of N, treat current tier as one level higher for compute policy.

--------------------------------------------------
3) Re-render Minimization Strategy (Actionable)
--------------------------------------------------

State architecture
- Split state slices (`data`, `interaction`, `validation`, `clipboard`, `derived`) and subscribe narrowly.
- Keep `draft` updates local to edited cell path; avoid replacing whole `cells` matrix object each keystroke.

Component boundaries
- Render cell component as pure/memoized unit keyed by stable cell id.
- Keep sticky layout components separate from body-grid components.
- Overlays (selection/highlight) should read interaction state without re-rendering every cell.

Update patterns
- Use batched updates for multi-cell operations (paste/delete range).
- Use immutable but shallow-changed structures (row-level replacement instead of full 2D clone where possible).
- Derived selectors must cache by relevant dependency keys.

Computation policy
- EV recompute from committed numeric values only.
- Cyclic/referenced compute runs on commit/paste batch end by default; not on every draft keystroke.

DOM/focus policy
- Central focus registry; do not recreate refs per cell render.
- Avoid dynamic inline style object churn in hot paths.

--------------------------------------------------
4) Virtualization Decision Rules
--------------------------------------------------

When to enable
- MUST enable virtualization if N > 900.
- SHOULD enable virtualization if N > 400 and measured p95 nav latency > 33 ms.
- SHOULD enable virtualization if horizontal overflow causes frame drops during drag selection.

What to virtualize first
- Priority 1: body rows.
- Priority 2: body columns (if very wide matrices).
- Keep sticky header/first column/frequency row/EV column outside or in synchronized pinned layers.

When not to virtualize
- N <= 400 and performance budgets met.
- If virtualization breaks keyboard/focus predictability and no robust focus adapter exists yet.

Operational rules
- Virtualization must preserve logical coordinate indexing.
- Off-screen selection ranges remain valid even if cells are not mounted.
- Scroll-to-focus logic must bring focused cell into viewport deterministically.

--------------------------------------------------
5) Instrumentation Plan (Manual QA Measurements)
--------------------------------------------------

What to measure per test matrix size (S/M/L/XL)

1. Key navigation latency
- Measure keydown timestamp to focused-cell visual update.
- Collect p50/p95 over 100 key presses.

2. Edit commit latency
- Measure Enter/Tab commit action to displayed committed value + mode change.

3. Paste latency + quality
- Measure paste start to final applied state.
- Log counts: applied, skippedReadonly, skippedInvalid, skippedOverflow.

4. Re-render intensity
- Record renders per keystroke for:
  - active cell,
  - row,
  - whole grid.
- Goal: active-cell edit should not trigger full-grid re-render.

5. Frame smoothness during drag selection
- Observe dropped frames / jank while drag-selecting across viewport.

6. Compute timing
- Measure EV recompute duration and cyclic compute total (iterations used + status).

7. Memory snapshot trend (optional but recommended)
- Compare before/after large paste and repeated edits for leak suspicion.

How to record (practical)
- Add lightweight dev timing marks around key handlers, commit pipeline, paste apply, and compute pipeline.
- Use browser Performance panel in manual QA runs.
- Save QA run sheet with matrix size, feature flags, p95 metrics, and pass/fail against budgets.

--------------------------------------------------
6) Engineering Decision Triggers
--------------------------------------------------

Trigger A: Move to row virtualization
- If Tier L matrices exceed 33 ms p95 navigation or drag updates.

Trigger B: Defer expensive compute
- If commit + compute exceeds 50 ms p95 in Tier M+.

Trigger C: Refactor state granularity
- If single-cell edit causes > 20 cell re-renders on average in Tier M.

Trigger D: UI density fallback
- If compact mode still cannot maintain <= 33 ms p95 at Tier L, auto-reduce non-essential overlays.

--------------------------------------------------
7) Non-Negotiable Performance Guarantees
--------------------------------------------------

1. Keyboard navigation remains responsive under target matrices.
2. Invalid draft handling never blocks typing.
3. Paste uses single batch apply + single undo step.
4. Compute failures/instability states do not freeze input pipeline.
