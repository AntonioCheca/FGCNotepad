Scenario Table Serialization Contract (Backward-Compatible)

Goal
- Define a safe, versioned JSON contract so old posts keep loading and new matrix features can evolve without data loss.

--------------------------------------------------
1) Versioned JSON Schema Plan (v1 -> v2)
--------------------------------------------------

Contract envelope (all versions)
- `type`: `scenario-table`
- `version`: number
- `payload`: object

v1 (legacy-compatible baseline)
- Purpose: current/old posts.
- Required payload keys:
  - `rows: string[]`
  - `columns: string[]`
  - `values: (number | string)[][]` (legacy ambiguity tolerated)
- Optional payload keys (must be honored when present):
  - `rowFrequencies: (number | string)[]`
  - `columnFrequencies: (number | string)[]`
  - `expectedValue: number | string`
  - `derivedMetrics: object`

v2 (typed matrix model)
- Purpose: new editor + advanced cells.
- Required payload keys:
  - `schemaVersion: 2`
  - `matrixId: string`
  - `rows: string[]`
  - `columns: string[]`
  - `cells: MatrixCell[][]`
  - `rowFrequencyCells: MatrixCell[]`
  - `columnFrequencyCells: MatrixCell[]`
  - `expectedValueCell: MatrixCell`
  - `meta: object`
- Optional payload keys:
  - `selectionSnapshot` (non-critical UI state)
  - `computeGraphMeta`
  - `migrationMeta`

Version strategy
- Reader MUST support `v1` and `v2`.
- Writer SHOULD emit `v2` once migration is enabled.
- If repo needs staged rollout, writer MAY emit v1-compatible shadow fields for one transition window.

--------------------------------------------------
2) Backward Compatibility Rules
--------------------------------------------------

Load rules for old posts
- If `version` missing and legacy shape detected (`rows/columns/values`), treat as implicit `v1`.
- Missing optional fields in v1 MUST be synthesized with safe defaults:
  - `rowFrequencies`: equal distribution over rows.
  - `columnFrequencies`: equal distribution over columns.
  - `expectedValue`: recompute from available numeric values/frequencies; fallback `0` if unavailable.
- String placeholders in `values` (e.g., `""`, `"-"`) MUST be preserved as draft-equivalent in normalized state.

Round-trip rule
- Loading v1 then saving as v2 MUST preserve all representable user content.
- Unknown legacy keys MUST be retained in `meta.legacyExtras` to avoid silent loss.

--------------------------------------------------
3) Forward Compatibility Fallback Behavior
--------------------------------------------------

Unknown future version handling
- If `version > supportedMax`:
  - Attempt permissive parse of known keys.
  - Preserve unknown fields under `meta.unparsedFields` (opaque JSON blob).
  - Render matrix in safe degraded mode (readonly if needed) rather than failing hard.

Unknown cell kinds/fields in v2+
- Unknown `cell.kind` MUST downgrade to readonly-static placeholder with preserved raw payload.
- Unknown fields inside known cell kinds MUST be retained on re-serialize.

Corruption tolerance
- If payload is partially invalid, loader SHOULD salvage valid sections (rows/columns/cells) and mark warnings.
- Hard-fail only when essential structure is absent (cannot infer dimensions).

--------------------------------------------------
4) Migration Policy During Load (Normalize Old Data)
--------------------------------------------------

Normalization pipeline

1. Detect version/shape
- `v2` explicit -> typed parser.
- `v1` explicit/implicit -> legacy parser.

2. Structural normalize
- Ensure rectangular matrix shape:
  - row count == values length
  - each row length matches columns length (pad with empty draft cells; clip overflow with warning)

3. Semantic normalize
- Convert v1 `values` into typed cells:
  - numeric -> committed-valid value cell
  - string token -> draft-preserved value cell
- Convert frequency arrays into typed frequency cells.
- Convert EV scalar to computed-readonly EV cell.

4. Metadata hydrate
- Add provenance defaults (`source: import`, `revision: 1`, timestamp optional).
- Attach load warnings for repaired dimensions/range issues.

5. Commit normalized state
- Internal state always becomes typed normalized model.
- Serializer writes v2 contract (unless compatibility flag requires v1 output).

--------------------------------------------------
5) “Never Lose User Data” Checklist
--------------------------------------------------

1. Preserve unknown keys from any version in metadata passthrough.
2. Never silently drop frequencies/EV/derived metrics during export.
3. Preserve draft text tokens that are not valid numbers yet.
4. Keep raw payload snapshot on parse warning for recovery/debug.
5. Do not coerce invalid tokens into `0` without explicit migration rule and warning.
6. On shape mismatch, pad/clip deterministically and record exact repair actions.
7. Unknown cell kinds downgrade to readonly placeholders, not deletion.
8. Re-serialize should include untouched opaque fields when possible.
9. Failed partial parse should still load salvageable content readonly.
10. Add round-trip tests: legacy -> normalize -> serialize -> reload equality checks.

--------------------------------------------------
6) File-Level Impact Map
--------------------------------------------------

`frontend/src/components/lexical/ScenarioTableNode.tsx`
- Add explicit versioned payload in `exportJSON` (v2 primary).
- Update `importJSON` to support:
  - implicit/explicit v1 normalization path,
  - v2 typed path,
  - unknown-version degraded fallback.
- Ensure frequencies/EV/typed cell metadata are included both directions.
- Preserve unknown fields in metadata passthrough object.

`frontend/hooks/useScenarioTableState.tsx` and `frontend/services/ScenarioTableService.tsx`
- State hook becomes normalization boundary output consumer (typed normalized model only).
- Service methods operate on typed cells, not mixed `number|string` arrays.
- Add adapter helpers for legacy numeric matrix consumers (e.g., solver input) without mutating stored draft values.

Editor load/save plugins
- `frontend/src/components/lexical/RestoreFromLocalStoragePlugin.tsx`
  - Save/load must preserve node JSON exactly (including unknown fields).
  - On load parse warnings, keep recoverable content and surface non-blocking warning.
- `frontend/src/components/forum/PostEditor.tsx`
  - Ensure node registration and parser path can load new versioned scenario-table payloads.
  - Maintain compatibility for old serialized documents stored in local storage/backend.

--------------------------------------------------
7) Practical Release Strategy
--------------------------------------------------

Phase A
- Add dual-read support (v1 + v2), keep current write behavior.

Phase B
- Enable v2 write with migration-on-load normalization.

Phase C
- Monitor warning telemetry and salvage rate; keep v1 read indefinitely for old posts.
