Matrix Clipboard Paste Spec v0 (TSV/CSV Blocks)

Purpose
- Support practical multi-cell paste from spreadsheets into the payoff matrix without breaking normal single-cell editing.

--------------------------------------------------
1) Parsing Rules
--------------------------------------------------

Input source
- Paste MUST read plain text from clipboard (`text/plain`).
- If clipboard text is empty, paste MUST no-op.

Delimiter detection
- Parser MUST attempt TSV first.
- TSV detection rule: if any line contains a tab (`\t`), parse as TSV.
- If no tabs are found, parser MUST fallback to CSV parsing.

Newline handling
- Parser MUST normalize line endings (`\r\n`, `\r`) to `\n`.
- Trailing final newline MUST be ignored.
- Blank interior lines MUST be preserved as empty rows (to avoid shape drift).

Quoted fields policy
- CSV mode MUST support RFC4180-style quotes:
  - `"value,with,comma"` stays one field.
  - escaped quote `""` resolves to `"`.
  - newlines inside quoted fields SHOULD be supported; if unsupported in v0 implementation, paste MUST fail-fast with warning (not partial parse).
- TSV mode SHOULD treat quotes as literal characters (no special quote parsing) for v0 simplicity.

Cell text normalization
- Parsed tokens MUST preserve raw text initially.
- Numeric/domain coercion MUST happen at write/validation stage per target cell type (payoff vs frequency vs readonly/computed).

Single-value paste behavior
- A 1x1 parsed block MUST behave like normal single-cell edit of the focused/anchor cell.

--------------------------------------------------
2) Placement Rules
--------------------------------------------------

Anchor
- Paste anchor MUST be the active cell (if none, focused cell).
- Parsed block top-left maps to anchor coordinate.

Mapping
- Block cell (r,c) maps to target (anchorRow + r, anchorCol + c).
- Placement MUST be rectangular based on parsed dimensions.

Clipping and overflow
- Targets outside matrix bounds MUST be clipped (ignored), not expanded in v0.
- Paste operation MUST continue for in-bounds cells even when overflow occurs.

Selection interaction
- If a range is selected, v0 MUST still use active cell as anchor; selected range is not a hard paste mask.
- Optional post-v0 enhancement: range-repeat/fill semantics.

Frozen rows/columns
- Frozen UI does not change coordinate mapping.
- Header/action control cells are non-paste targets.

--------------------------------------------------
3) Conflict Rules
--------------------------------------------------

Readonly/computed targets
- Readonly/computed cells MUST be skipped.
- Skipped cells MUST NOT block writes to other cells in same paste.

Partial overwrite
- Paste MUST overwrite writable target cells exactly once.
- Existing values in writable targets are replaced by parsed inputs (subject to validation).

Validation conflicts
- If token is invalid for target cell type:
  - cell write MUST be rejected for that cell,
  - other valid cells in same paste MUST still apply.

Mixed target classes
- In mixed blocks (payoff + frequency + readonly), per-cell rules apply independently.

--------------------------------------------------
4) Error Handling UX Policy
--------------------------------------------------

Default philosophy
- Do not interrupt fast workflow; allow partial success with concise feedback.

Warnings vs silence
- v0 MUST be silent for pure success.
- v0 MUST show a compact non-blocking summary warning when any cell is skipped/rejected, e.g.:
  - "Paste applied to 8 cells; 3 skipped (2 readonly, 1 invalid)."

When to hard-fail
- Paste MUST hard-fail (no writes) only when parsing fails globally (malformed CSV quote state / unsupported multiline quoted CSV if not implemented).
- Hard-fail MUST show one clear message and keep prior data intact.

Visual feedback
- Successfully written cells SHOULD receive transient highlight.
- Invalid/skipped targets SHOULD not flash as successful.

--------------------------------------------------
5) Undo Granularity Recommendation
--------------------------------------------------

Recommendation: single undo action per paste.

Rationale
- Spreadsheet expectation: one Ctrl+Z reverts whole paste, not one cell at a time.
- Prevents long undo chains for large blocks.
- Keeps mental model clear for reviewers/correctors doing correction passes.

Requirement
- All per-cell writes from one paste event MUST be committed in one transaction/update batch.

--------------------------------------------------
6) Concrete Paste Test Vectors (10)
--------------------------------------------------

Assumptions for vectors
- Matrix body size in examples: 4x4 writable payoff cells unless stated.
- Anchor in examples: (row2,col2) unless stated.
- Row1/Col1 in examples are regular data cells, not headers.

1) Basic TSV 2x2
- Input: `1\t2\n3\t4`
- Target: all writable in-bounds
- Expected: 4 cells written to (2,2)-(3,3), success, no warning.

2) CSV fallback 2x3
- Input: `1,2,3\n4,5,6`
- Expected: parsed as CSV (no tabs), 6 cells written to (2,2)-(3,4), no warning.

3) TSV with trailing newline
- Input: `7\t8\n9\t10\n`
- Expected: trailing newline ignored, 2x2 write, no extra blank row.

4) CSV quoted comma
- Input: `"12,5",9`
- Expected: first token kept as `12,5` text then validated by target type; second token `9`; if first token invalid numeric -> first cell skipped, second applied, warning summary.

5) Overflow clipping right/bottom
- Input: `1\t2\t3\n4\t5\t6\n7\t8\t9`
- Anchor: (3,3) on 4x4 body
- Expected: only in-bounds cells written ((3,3),(3,4),(4,3),(4,4)); overflow cells clipped; warning with skipped overflow count.

6) Readonly intersection
- Input: `11\t12\n13\t14`
- Condition: target (2,3) is readonly/computed
- Expected: 3 cells written, readonly cell unchanged, warning reports readonly skip.

7) Mixed valid/invalid numeric
- Input: `5\tabc\n-3\t2`
- Expected: valid numeric targets updated (`5`,`-3`,`2`), `abc` rejected for numeric payoff cell, warning reports invalid count.

8) Single cell plain value
- Input: `42`
- Expected: acts as normal single-cell paste to anchor only, one-cell overwrite, no range behavior.

9) Empty fields in TSV
- Input: `1\t\n\t4`
- Expected: empties map as empty-string tokens; writable targets receive empty draft/default per cell policy; 4 in-bounds targets processed.

10) Malformed CSV quote (global parse fail)
- Input: `"1,2\n3,4`
- Expected: no cells written, one hard-fail warning (parse error), undo stack unchanged.
