Cyclical Reference Evaluation Semantics v0 (Deterministic, Explainable)

Goal
- Support cyclic matrix references in MVP with predictable outputs and clear user messaging.
- Prioritize stable, repeatable behavior over mathematically exact equilibrium solving.

--------------------------------------------------
1) Evaluation Algorithm Options
--------------------------------------------------

Option A: Fixed Iteration Only

Definition
- Evaluate all computed cells in dependency-aware passes for exactly N iterations (e.g., N=5), starting from deterministic initial values.

Pros
- Fully deterministic and easy to explain.
- Runtime cost is bounded and predictable.
- No threshold tuning complexity.

Cons
- May stop far from stable value in slow-converging systems.
- "Why this number?" can be less satisfying for technical users.


Option B: Convergence Threshold Only

Definition
- Iterate until max absolute cell delta <= epsilon (e.g., 0.001), with a hard safety cap.

Pros
- Better approximation when systems converge quickly.
- Output quality can be higher than fixed iteration for same average cost.

Cons
- Less predictable iteration count.
- Threshold/scale effects can confuse users (small vs large magnitude cells).
- More branching behavior to explain.


Option C: Hybrid (Fixed Iteration + Early Convergence Check)

Definition
- Run up to maxIterations; stop early if convergence threshold met for K consecutive rounds.

Pros
- Bounded runtime + potential early completion.
- More robust than fixed-only for easy cases.

Cons
- Slightly more complex messaging.
- Additional policy knobs (epsilon, K, maxIterations).

--------------------------------------------------
2) Recommended MVP Policy
--------------------------------------------------

Recommendation: Hybrid with deterministic defaults, reported as fixed-loop approximation.

Policy
- Initialization:
  - Start every computed cyclic cell from a deterministic seed value:
    - previous committed computed value if available,
    - else 0.0.
- Iteration budget:
  - `maxIterations = 5` (MVP default).
- Convergence check:
  - `epsilon = 0.001` absolute delta.
  - Mark `converged` only if threshold met for 2 consecutive rounds.
  - Early-stop if converged; otherwise stop at iteration 5.
- Determinism guarantees:
  - Evaluate cells in stable sorted coordinate order (matrixId, row, col).
  - Use snapshot-at-round-start semantics (Jacobi-style) so order does not change math outcome within a round.
  - Round final displayed numeric value to product display precision (e.g., 2 decimals) but keep internal precision higher.

Rationale
- Keeps "4-5 loops" product idea.
- Guarantees bounded runtime and repeatability.
- Gives a straightforward user explanation: "approximation from up to 5 loop passes."
- Avoids full nonlinear solver complexity in MVP.

--------------------------------------------------
3) User-Facing Explanation Strategy
--------------------------------------------------

Primary message (short)
- "Approximate value (loop-evaluated, up to 5 passes)."

Secondary detail (expandable)
- "This cell depends on a feedback loop. We recompute it repeatedly and stop when stable or after 5 iterations."

Status labels
- `Stable approximation` (converged before cap)
- `Capped approximation` (hit max iterations)
- `Unstable loop` (divergent/oscillating beyond tolerance)
- `Evaluation error` (invalid dependency/math error)

Explainability panel fields
- Iterations used
- Last max delta
- Dependency count
- Loop group id (for cross-matrix cycles)

Tone guidance
- Avoid saying "exact" for cyclic values.
- Use "approximate" consistently in badges/tooltips.

--------------------------------------------------
4) Failure / Instability Handling States
--------------------------------------------------

Per-cell compute status states

1. `ok_converged`
- Reached threshold before max iterations.

2. `ok_capped`
- Did not converge but produced bounded approximation at iteration cap.

3. `unstable_oscillating`
- Alternating pattern detected (delta does not trend down, sign/magnitude flip cycle).

4. `unstable_diverging`
- Magnitude grows beyond divergence guardrail.

5. `dependency_missing`
- Referenced cell/matrix not found.

6. `eval_error`
- Formula parse/runtime error, NaN/Infinity encountered.

MVP behavioral policy
- `ok_converged` and `ok_capped`: show numeric result + status badge.
- `unstable_*`: keep last finite iteration value, flag with warning badge.
- `dependency_missing` / `eval_error`: cell shows error token (not numeric), excluded from downstream numeric aggregation unless explicit fallback exists.
- System MUST never crash evaluation graph due to one failing loop; isolate per strongly connected component.

Guardrails
- Hard cap per SCC: maxIterations.
- Numeric sanity checks each round: reject NaN/Infinity.
- Divergence threshold (example): absolute value exceeds configured cap (e.g., 1e6) -> mark `unstable_diverging`.

--------------------------------------------------
5) Scenario Examples (6)
--------------------------------------------------

Example 1: Direct self-reference damping
- Formula: A = 0.5 * A + 4
- Seed A0 = 0
- Iterations (5): 4.0, 6.0, 7.0, 7.5, 7.75
- Outcome: `ok_capped` (or `ok_converged` if epsilon reached with chosen precision).
- User text: "Approximate value after 5 passes."

Example 2: Direct self-reference unstable growth
- Formula: A = 1.2 * A + 3
- Seed A0 = 0
- Sequence grows each pass.
- Outcome: `unstable_diverging` once guardrail exceeded or trend detected.

Example 3: Two-cell same-matrix loop
- A = B + 1
- B = 0.5 * A
- Seed A0=0, B0=0
- Deterministic Jacobi rounds produce bounded approach.
- Outcome: usually `ok_converged` or `ok_capped` depending epsilon/cap.

Example 4: Cross-matrix loop (Matrix X <-> Matrix Y)
- X!A references Y!B * 0.8
- Y!B references X!A + 2
- SCC spans two matrices; evaluated together by stable coordinate order.
- Outcome: deterministic approximate status with loop group id shared across both cells.

Example 5: Loop with manual override break
- A (computed cyclic) feeds B, but B is locked manual override = 5.
- Evaluation uses B effective override value, reducing loop feedback.
- Outcome: stable value often achieved faster; provenance shows override participation.

Example 6: Missing cross-matrix dependency inside loop
- A references Z!C, but matrix Z is unavailable.
- Outcome: `dependency_missing`; A not numerically computed, downstream cells depending on A become `eval_error` or propagate missing-dependency status per policy.

--------------------------------------------------
6) Determinism and Explainability Rules (Normative)
--------------------------------------------------

- The same input snapshot MUST produce the same cyclic outputs and statuses.
- Evaluation order MUST be stable and documented.
- Cyclic results MUST always carry an approximation status label.
- UI SHOULD provide one-click detail showing iterations and stop reason.
- Cyclic evaluation MUST be bounded in time and isolated from non-cyclic cells.
