# Matrix Editor Phased Execution Roadmap v1.1

## Strategic Clarifications Incorporated

Core product direction now clarified:

* **Not a full spreadsheet.** This is a compact matrix editor for numeric scenario data.
* **Primary jobs:** fast entry, fast review, trustworthy reading.
* **Typical size targets:**

  * 5x5 = excellent experience
  * 10x10 = comfortable / mostly visible
  * 15x15 = acceptable with scroll
* **Mobile:** explicitly de-scoped for now.
* **Third-party grid dependency:** avoid commercial lock-in; prefer custom or lightweight permissive foundation only.
* **Cell types now simplified:**

  * static numeric value
  * scenario reference (computed from linked matrix)
* **Critical UX truth:** users must always know current row action + current column action.
* **Not needed now:** formatting, merged cells, autofill, advanced spreadsheet parity, huge-scale 40x40 optimization.

# Global Product Rules

## Must Feel Like

A lightweight tactical grid with spreadsheet ergonomics:

* click to select
* double click / Enter to edit
* arrows navigate
* paste blocks
* clear values quickly
* compact dense reading

## Must Not Become

* formatting spreadsheet
* business spreadsheet
* formula language platform
* giant enterprise grid
* mobile-first editor
* style customization tool

## Golden UX Requirement

At all times, the user should be able to confidently understand:

* which **Player 1 action row** they are in
* which **Player 2 action column** they are in
* what value belongs to that interaction

This is as important as editing itself.

# Phase 1: Foundation + Domain Contracts

## Goal

Build safe architecture and lock the domain rules before UI acceleration.

## Deliverables

* Typed grid state skeleton:

  * data
  * selection
  * editing
  * validation
  * derived
  * viewport
* Serialization dual-read contract.
* Legacy adapter layer from current matrix structures.
* Monolith decomposition plan for current huge files.
* Explicit non-goals document.
* Summary row/column rules contract.
* Baseline performance instrumentation.

## New Required Decisions in This Phase

### Summary Axis Rules

Define clearly:

* final row = opponent expected usage input
* final column = player optimal usage derived
  (or final chosen mapping after decision)

Lock behavior now to avoid later confusion.

### Save Model

Persist raw intent:

* static cells save raw numeric value
* reference cells save linked scenario id + cached computed value
* preserve metadata for future editing

## Definition of Done

* Old matrices load correctly.
* No data-loss on save/reload.
* Legacy data normalized into typed state.
* Summary axes have written rules.
* Non-goals approved.
* Current huge files mapped into future module ownership.

## Rollback

Use legacy renderer/state path behind flag.

# Phase 2: Core Spreadsheet Interaction MVP

## Goal

Deliver the first version that already feels meaningfully better than current UX.

## Deliverables

## Selection / Modes

* Single click selects cell.
* Active cell clearly highlighted.
* Separate modes:

  * view mode
  * edit mode

## Editing Rules

* Double click enters edit mode.
* Enter enters edit mode if selected.
* Enter while editing commits value and remains on same cell.
* Typing while selected enters overwrite edit mode.
* Esc cancels edit (nice-to-have but included if low cost).

## Navigation Rules

* Arrow keys move selection.
* Navigation in view mode only.
* While editing, arrows follow text cursor behavior.

## Clearing Rules

* Backspace/Delete on selected editable cell clears value.
* Readonly cells ignore mutation actions.

## Clipboard

* Paste TSV first, CSV fallback.
* Multi-cell paste from selected origin.
* Clip overflow safely.
* Warn on skipped readonly/invalid targets.

## Validation

* Numeric only:

  * integers
  * decimals
  * negative if allowed by domain
* Invalid drafts visible without breaking flow.

## Readability UX (moved earlier)

* Sticky headers or equivalent row/column anchors.
* Strong active row/column cues.
* Keep row and column labels visible during scroll where possible.

## Definition of Done

* 5x5 matrix feels excellent.
* 10x10 matrix feels clearly usable.
* Core smoke suite passes.
* Paste works for common spreadsheets.
* User never loses track of row/column context.

## Rollback

Fallback to simpler single-cell legacy behavior.

# Phase 3: Reference Cells + Computed Values

## Goal

Support scenario-linked cells in a clean, understandable way.

## Deliverables

## Cell Types

* Static numeric
* Reference/computed

## Visual Language

Reference cells must look clearly different:

* color tint / badge / icon
* still show final numeric result in grid

## Edit Experience

Editing a reference cell opens selector flow:

* modal or panel
* searchable scenario list
* choose linked scenario
* preview selected target if possible

## Computation Rules

* Grid displays resolved final average/value.
* Save raw reference + computed cache.

## Mixed Selection Rules

* Paste/delete only affects editable static cells.
* Reference cells skipped with feedback.

## Provenance

Inspect source of value:

* linked scenario name
* source id
* last computed value

## Definition of Done

* Reference cells are understandable at a glance.
* Users can relink safely.
* Serialization preserves links + values.
* Mixed operations behave predictably.

## Rollback

Disable reference editing UI while preserving rendered values.

# Phase 4: Density, Performance, Hardening

## Goal

Polish usability at target sizes and finalize release confidence.

## Deliverables

## Density

Default density prioritizes visible cells.

Optional later toggle:

* compact
* standard

(Only if worthwhile after testing.)

## Performance Targets

Focus on real sizes:

* 5x5
* 10x10
* 15x15

No overengineering for 40x40.

## Quality

* Full manual QA
* Known edge-case registry
* Regression pass in forum embedding context
* Release checklist

## Definition of Done

* 5x5 excellent
* 10x10 comfortable
* 15x15 acceptable
* No major focus bugs in editor embedding
* Known issues documented

## Rollback

Disable optional density enhancements, retain core editor.
